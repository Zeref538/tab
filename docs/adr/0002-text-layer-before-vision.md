# 0002 — Route to the text layer before reaching for the vision model

Date: 2026-08-28
Status: accepted

## Context

Receipts arrive in two very different shapes. Some are PDFs generated by
software — an e-receipt, an emailed invoice, a bank statement — and they carry a
real text layer, meaning the characters are stored as characters and can simply
be read. Others are photographs of paper: crumpled, angled, faded thermal ink,
taken in bad light.

Reading them the same way is wrong in both directions. Sending a text-layer PDF
to a vision model throws away perfect data and replaces it with a guess, slowly.
Trying to parse a photograph as text finds nothing at all.

This is also the decision that makes TAB an agent rather than a batch job. If
there were one fixed path, there would be nothing to decide.

## Options

- **Vision for everything.** One code path, no branch, and it works on both
  shapes. It is also slower by roughly the cost of a model pass per document, and
  it degrades data that was already exact. Accuracy goes *down* on the easy half.
- **Text layer for everything, OCR as a preprocessing step.** Run OCR on images
  first, then treat everything as text. Adds a second engine to install and tune,
  and OCR on a crumpled thermal receipt produces confident nonsense that reads
  like real text — which is worse than no text, because the arithmetic check is
  then run on garbage that parses.
- **Route per document**, and log the reason.

## Decision

**Route per document.** Extract the text layer; if the count of extractable
characters clears a threshold, parse it directly with no model involved.
Otherwise render the page to an image and use the vision model.

The threshold is a named constant, not a literal buried in an `if`. A scanned PDF
often carries a handful of stray characters from a header stamp, so "has any
text" is the wrong test and "has enough text to be a receipt" is the right one.

Both routes emit the same JSON shape and pass through the same checks. The route
only decides how the numbers were obtained, never whether they are trusted.

## Consequences

- The easy half of the corpus costs nothing: no model, no GPU, no wait. That is
  a large part of why this runs for free.
- The routing decision is logged to `decisions` with its reason, so the demo can
  show *why* a document took the path it did.
- **A test asserts the model was never invoked for a text-layer PDF.** Without it,
  a refactor can quietly route everything through vision and nobody notices
  except the electricity bill.
- The threshold needs tuning against real files. It is a calibration knob, and
  the first value is a guess by definition.
- If both routes run on the same document — which happens on a retry — their
  agreement becomes a check in its own right, and agreement between two
  independent methods is worth more than either one claiming confidence. See
  [0003](0003-confidence-from-checks-not-the-model.md).
