A receipt that disagrees with itself was misread, and you know that without a model being involved at all.

A local vision model proposes a structured receipt; deterministic Python decides. Seven arithmetic checks run three-state, pass, fail or skip, and a check that could not run has not passed. Model confidence is recorded and never read by anything that decides. Rows that reconcile are committed to SQLite unattended; the rest escalate with the disputed field named.

    02The premise

    A model will hand you a wrong total and sound completely certain

    Confidence is not a measurement, so nothing here reads it

    Ask a model how sure it is and you get a number that feels like evidence and is not. It will state a total it never properly saw with the same steadiness it uses for one it read perfectly. So TAB never asks.

    Model self-report is recorded in the run metadata and read by nothing that decides. The verdict comes from arithmetic over the extracted fields, which is checkable without any reference to the extractor.

    A receipt is unusual: it carries its own proof. The items add up to the subtotal. The subtotal plus VAT makes the total. The VAT is 12% of the VATable sales. Add it back up, and a receipt that disagrees with itself was misread. You know that without a model being involved at all.

    The guard is redundancy already printed on the document. Seven checks run three-state: pass, fail, or skip when an input is missing. A skip is not a pass, and that distinction is what stops an unreadable receipt being filed as a clean one.

    03The route

    The cheapest way to read a receipt is not to read it at all

    Text-layer extraction first, vision model only where there is no text

    A PDF from an online order already contains its words. Opening it and taking them is free, instant, and cannot be wrong. Only a photograph needs a model. Choosing the wrong route costs you either accuracy or a lot of time.

    Routed on extractable character count: above the threshold the text layer is parsed directly by tab.pdftext, below it the page is rasterised and passed to the vision model. See docs/adr/0002.

    Labels are matched by likeness, not spelling

    A camera reads SUBTOTAL as Sabtotal and VAT AMOUNT as UAI Amount, and an exact pattern misses both. One wrong letter used to switch off the strongest check in the project without saying so.

    05The screen

    It shows you the paper and says what is wrong with it

    The review queue, with the disputed field named rather than scored

    Not "confidence 0.62". A sentence you can act on: which line disagrees, what it should have been, and what the receipt says instead. You fix the one field and approve, or you throw it back.

    Served by tab.web on 127.0.0.1 only. Corrections are written to their own table, so a later version can be measured against what a person actually changed rather than against a guess at it.

    07What broke

    The retry was built, measured, and then deleted

    Three findings that changed the code, one of which removed a feature

    The plan called for reading a doubtful receipt a second time, a different way. It was built. Sixty seven second readings changed one verdict and cost most of a minute each. So it came out again.

    Re-reading at higher DPI with an alternate prompt: 67 retries, one verdict change, 86 percent more time per checked receipt. Removed, with the reasoning kept in docs/adr/0011.

    The reader leaked memory, and it was not a leak

    Resident memory climbed twenty four megabytes a receipt, dead linear, past a gigabyte after forty. The arrays were cyclic garbage, and Python decides when to collect by counting objects waiting, not bytes. Ninety megabytes there is a couple of dozen arrays, far too few to trip it. One explicit collect holds it flat.

    08What it will not do

    The numbers come from Indonesian receipts, so no Philippine claim is made

    Corpus scope, and the fields this corpus cannot score

    CORD is a corpus of Indonesian receipts; it has no BIR-style VAT breakdown, no TIN, no OR number. It measures whether a small local model can read a photograph of a receipt at all, and nothing more.

    No Philippine accuracy figure appears anywhere on this page

    A hand-labelled Philippine set is the gate for that, and it does not exist yet. A test in this repo fails if such a figure is ever added without one.

    It also does not read handwriting, does not convert currencies, and does not split a senior or PWD discount into its parts. It captures that discount as one amount and says so.

    Non-goals are listed in docs/PRD.md and enforced by the schema: discount_total is a single field with no decomposition.

    09Run it yourself

    One command to install, one to read a folder

    Install, ingest, export. No API key, no GPU, no account

    pip install git+__REPO__

    Then point it at a folder. It reads what is in there, files what adds up, and leaves the rest on your screen with the bad line named.

    The vision route needs Ollama with qwen2.5vl:3b pulled. The OCR route needs neither: pip install "tab-agent[ocr]" and no model server at all.

    Everything runs on your own machine and the review screen binds to localhost only, because receipts are personal data and there is nowhere for them to go.

    The model can be wrong and sound certain. The arithmetic cannot.
